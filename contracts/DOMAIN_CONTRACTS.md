# Domain / Repository Contracts

These are Kotlin-level contracts, not HTTP endpoints. Adapt naming to the repository conventions.

## Domain result types

```kotlin
sealed interface AppResult<out T> {
    data class Success<T>(val value: T) : AppResult<T>
    data class Failure(val error: DomainError) : AppResult<Nothing>
}

sealed interface DomainError {
    data object InvalidQuantity : DomainError
    data object ActivityDisabled : DomainError
    data object RewardRuleMissing : DomainError
    data object DailyLimitExceeded : DomainError
    data object InsufficientAvailableBalance : DomainError
    data object InsufficientSavingsBalance : DomainError
    data object DuplicateRequest : DomainError
    data object CurrencyLocked : DomainError
    data object InvalidAmount : DomainError
    data object ParentAuthenticationRequired : DomainError
    data object ParentLockedOut : DomainError
    data object TransactionNotReversible : DomainError
    data object BackupInvalid : DomainError
    data class Unexpected(val safeMessage: String) : DomainError
}
```

## Transaction command requirements

Every money-changing command must include:
- idempotency key
- requested amount (if applicable)
- operation-specific reference
- timestamp generated by trusted app/domain clock

Do not accept a caller-supplied arbitrary balance.

## Reward posting pseudocode

```kotlin
suspend fun submit(request: ActivitySubmissionRequest): ActivitySubmissionReceipt =
    database.withTransaction {
        if (submissionDao.existsByIdempotencyKey(request.idempotencyKey)) {
            throw DuplicateRequest
        }

        require(request.quantity > 0)
        val activity = activityDao.getEnabled(request.activityKey) ?: throw ActivityDisabled
        val rule = rewardRuleDao.getEffectiveRule(activity.id, clock.now()) ?: throw RewardRuleMissing

        validateDailyLimits(request, rule)

        val totalMinor = Math.multiplyExact(rule.rewardPerUnitMinor, request.quantity)
        val transactionId = uuid()
        val submissionId = uuid()

        insertSubmissionWithAppliedRuleSnapshot(...)
        insertLedgerTransaction(...)
        insertLedgerEntries(
            availableAccount to totalMinor,
            rewardFundAccount to -totalMinor
        )

        validateTransactionBalances(transactionId)
        return receiptWithNewBalances(...)
    }
```

The code must handle duplicate idempotency keys safely. Returning the existing receipt for an exact retry is preferable to showing an error, provided the request payload matches the original. If the same key is reused with a different payload, reject it.

## Savings transfer pseudocode

```kotlin
database.withTransaction {
    require(amountMinor > 0)
    val available = calculateAvailableBalance()
    if (available < amountMinor) throw InsufficientAvailableBalance

    insertBalancedTransaction(
        type = SAVINGS_TRANSFER,
        entries = listOf(
            availableAccount to -amountMinor,
            savingsAccount to amountMinor
        )
    )
    optionallyInsertGoalContribution(...)
}
```

## ViewModel conventions

- Expose `StateFlow<ScreenUiState>`.
- Use immutable UI state data classes.
- Use `viewModelScope.launch`.
- Do not do database or business calculations in Composables.
- UI events call ViewModel methods.
- Map DomainError to child-friendly or parent-appropriate copy.
